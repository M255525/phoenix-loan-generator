# 授權伺服器設定指南（教師專用，僅需設定一次）

這份工具頁面 banner 有一個「課程授權序號」欄位，需要連到你的 Google Sheet 確認序號是否還在 4 個月使用期限內，並在 banner 上顯示剩餘天數。這個檢查是透過 **Google Apps Script**（Google Sheet 內建、免費）架設的一支小型 API 完成的，需要你手動部署一次。部署完成後，往後每次開新班級只要在 Google Sheet 新增一列序號即可，不需要重新部署。

這支 Apps Script 同時也是「**課程內建 AI 服務**」的代理——學員不需要自己申請 API 金鑰，AI 優化功能會透過這支 Apps Script，用你設定在 Script Properties 裡的金鑰代打給服務商，金鑰不會出現在 `index.html` 裡、也不會傳到學員的瀏覽器。這個部分是選用的：如果你不設定任何內建金鑰，學員仍然可以在「AI 優化」卡片自行填入自己的 API 金鑰使用。

程式只會讀寫「序號」「開始日期」「結束日期」三欄，其餘欄位不會被動到。

## 部署步驟

1. 開啟上面的 Google Sheet。
2. 點選選單「**擴充功能（Extensions）→ Apps Script**」，會開啟一個新分頁的程式碼編輯器。
3. 把編輯器裡預設的 `function myFunction() {}` 全部刪除，貼上本資料夾 `Code.gs` 的完整內容，然後按左上角儲存（磁片圖示）。
4. 點右上角藍色「**部署（Deploy）→ 新增部署作業（New deployment）**」。
5. 左邊齒輪圖示選「**網頁應用程式（Web app）**」。
6. 設定：
   - 說明：可填「phoenix-loan-limit 授權檢查」
   - 執行身分（Execute as）：**我（你的帳號）**
   - 誰可以存取（Who has access）：**任何人（Anyone）** ← 這一步一定要選「任何人」，否則學員的瀏覽器連不到
7. 點「部署」。第一次部署會跳出 Google 的授權確認畫面（因為腳本要讀寫你的 Sheet）：
   - 選你的帳號 → 若出現「Google 尚未驗證這個應用程式」，點左下角「進階」→「前往 (不安全)」→ 允許。這是正常現象（因為這是你自己寫的腳本，沒有送 Google 審查），不是真的不安全。
8. 部署完成後會顯示一組網址，格式類似：
   ```
   https://script.google.com/macros/s/AKfycb.................../exec
   ```
   複製這組網址。

## 把網址接上工具

打開 `phoenix-loan-limit/index.html`，搜尋 `LICENSE_CHECK_URL`（大約在 JS 區塊最前面），把空字串改成剛剛複製的網址：

```js
const LICENSE_CHECK_URL = "https://script.google.com/macros/s/AKfycb.................../exec";
```

存檔即可。如果之後要重新打包桌面版 exe，記得改完 index.html 要重建（見 `CLAUDE.md`）。

## （選用）設定課程內建 AI 服務金鑰

如果希望學員完全不用自己申請 API 金鑰就能用 AI 優化，回到 Apps Script 編輯器：

1. 左側選單點齒輪圖示「**專案設定（Project Settings）**」。
2. 找到「**指令碼屬性（Script Properties）**」，點「新增指令碼屬性」。
3. 依你想開放的服務商，新增以下任一組或多組（**屬性名稱要完全一致**）：

   | 屬性名稱 | 對應服務商 |
   |---|---|
   | `CLAUDE_API_KEY` | Claude（Anthropic） |
   | `OPENAI_API_KEY` | OpenAI |
   | `GEMINI_API_KEY` | Gemini（Google） |
   | `OPENROUTER_API_KEY` | OpenRouter |

4. 值填你自己的 API 金鑰，儲存。**不需要哪個服務商都設，設哪個開放哪個就好**；沒設定的服務商，學員選到時會看到「教師尚未設定此服務商的內建金鑰」，可改選其他服務商或自行輸入自己的金鑰。

這組金鑰只存在 Script Properties，不會出現在 `Code.gs` 原始碼、也不會傳到學員瀏覽器——學員在「AI 優化」卡片把「API 金鑰」欄位留空即可使用。

## 驗證部署是否成功

部署完成的網址直接貼到瀏覽器網址列開啟（GET 請求），應該會看到：

```json
{"ok":true,"message":"授權伺服器運作中。請用 POST 傳送 JSON body，例如 {\"serial\":\"k9T2mP8x\"}"}
```

看到這個就代表部署成功。你也可以打開 `phoenix-loan-limit/index.html`，在頁面最上方 banner 的「課程授權序號」欄位填入 Sheet 裡現有的序號（例如目前表格中的 `k9T2mP8x`）並按「驗證」，看是否顯示「✓ 剩餘 N 天可用（至……）」。接著到「AI 優化」卡片，若已設定內建金鑰可直接留空 API 金鑰按下優化；若沒設定，填入你自己的 API 金鑰測試。

## 之後每次開新班級要做什麼

**不需要重新部署 Apps Script。** 只要：

1. 打開 Google Sheet，新增一列。
2. 「序號」欄填一組你要發給這班學員的序號（例如產生一組隨機英數字串）。
3. 「開始日期」「結束日期」兩欄**留空**——第一位學員第一次按下「AI 優化」時，系統會自動把「開始日期」寫成當下時間，「結束日期」自動算成開始日期 + 4 個月。
4. 把這組序號發給該班全體學員（同班共用同一組序號，所有人的起訖時間會一致）。

如果想手動指定某班的起訖日期（例如想讓有效期從開課日算起、而不是從第一次使用算起），也可以直接在 Sheet 手動填「開始日期」「結束日期」，系統偵測到已有值就不會覆蓋，直接以你填的日期為準。

## 修改「4 個月」這個期限

在 `Code.gs` 開頭的 `const VALID_MONTHS = 4;` 改掉這個數字，改完要回到 Apps Script 編輯器貼上新版程式碼，再「部署 → 管理部署作業 → 編輯 → 部署」一次（**部署網址不會變**，不需要再改 `index.html`）。

## 常見問題

- **學員按優化一直顯示「無法連線授權伺服器」**：先檢查 `LICENSE_CHECK_URL` 是否已經填好網址（不是空字串）；再檢查步驟 6 的存取權限是否真的選了「任何人」。
- **改了 Code.gs 之後網址失效或行為沒變**：Apps Script 修改程式碼後，必須到「部署 → 管理部署作業 → 編輯（鉛筆圖示）→ 版本選「新版本」→ 部署」才會生效，只存檔不會自動更新已部署的網址。
- **想收回某組序號的使用權**：把該列的「結束日期」改成一個過去的日期即可，之後驗證都會回傳逾期。
- **學員留空 API 金鑰卻顯示「教師尚未設定此服務商的內建金鑰」**：代表你在 Script Properties 沒有設定該服務商對應的屬性（見上方「設定課程內建 AI 服務金鑰」），請新增後再試，或請學員改選其他已設定的服務商／自行輸入金鑰。
- **內建 AI 服務會不會被序號以外的人濫用**：不會。`Code.gs` 的 `llm` 動作一定會先重新驗證序號有效才會呼叫服務商——即使有人繞過前端直接打 Apps Script 網址，沒有有效序號也拿不到任何回應。
